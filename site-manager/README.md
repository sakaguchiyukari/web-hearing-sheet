# Webサイト セキュリティ管理システム

自社で運営している複数のWebサイト（WordPress・静的HTML・bears CMS・その他）のセキュリティを、**チェックリストで点検し、ToDoで対応を管理する**ための社内システムです。サイト本体だけでなく、サーバー・ドメイン・SSL・バックアップ・外部診断もまとめて確認でき、上司向けの月次報告書（PDF・CSV・印刷）も作れます。

- 契約費用・支払い、パスワードの管理は**このシステムでは扱いません**（別システムで管理する前提）。

- 外部サービスとの同期や自動ログイン、外部サーバーへの自動アクセスは**一切行いません**。担当者が手動で記録します。
- データは**このPCの中（`data` フォルダ）だけ**に保存されます。
- 初期設定では**このPCからしか開けません**（社外・他のPCからはアクセス不可）。

設計の詳細（画面構成・データ設計・判定ルール）は [docs/DESIGN.md](docs/DESIGN.md) を参照してください。

---

## 1. 動作環境

| 項目 | 内容 |
|---|---|
| 必要なソフト | **Node.js 18.17 以上**（LTS版を推奨）。追加のインストールは不要です |
| ブラウザ | Google Chrome / Microsoft Edge（最新版推奨）。Safari・Firefox でも利用できます |
| OS | Windows / macOS / Linux |

Node.js が入っていない場合は https://nodejs.org/ja から「LTS」版をインストールしてください。

## 2. 起動方法

### かんたん起動（ダブルクリック）

| OS | 操作 |
|---|---|
| Windows | `start.bat` をダブルクリック |
| Mac | `start.command` をダブルクリック（初回は右クリック →「開く」） |

黒い画面（ターミナル）が開き、少し待つとブラウザで `http://127.0.0.1:3800/` が開きます。
**使っている間は黒い画面を閉じないでください。** 終了するときは黒い画面で `Ctrl + C` を押すか、画面を閉じます。

### コマンドで起動

```bash
cd site-manager
npm start        # または node server.js
```

ブラウザで http://127.0.0.1:3800/ を開きます。

### 初回のみ：管理者アカウントの作成

初めて開くと「管理者アカウントを作成してください」と表示されます。ユーザー名・表示名・パスワード（8文字以上）を設定してください。
ほかの担当者のアカウントは「設定・データ管理」画面から追加できます。

## 3. 使い方

左のメニューから各画面に移動します。上部の「＋ 点検を記録」「＋ 作業・トラブル」ボタンはどの画面からでも使えます。

| 画面 | できること |
|---|---|
| ダッシュボード | 件数サマリー、サイトごとの状態（色分け）、やること（ToDo）、対応中の問題、期限・予定（ドメイン・SSL・点検・ToDo）、点検が必要なサイト、バックアップの警告 |
| サイト管理台帳 | サイトの一覧・検索・絞り込み・追加。サーバー会社・ドメイン管理会社・ドメイン／SSLの有効期限を登録。サイト名をクリックすると詳細（概要／ToDo／点検履歴／バックアップ／セキュリティ／作業履歴のタブ） |
| セキュリティ点検 | サイトの種類ごとのチェックリスト（サイト本体・アカウント・サーバー・ドメイン・SSL・バックアップ・診断の分類つき）で結果を記録。「要確認・対応中」の項目はToDoに自動登録できます |
| ToDo（対応リスト） | やることの一覧。優先度・期限・担当者・分類で管理し、丸ボタンで完了。診断の指摘や不審ファイル検出も自動で登録されます |
| 作業履歴・トラブル | 作業とトラブルの記録・検索。未解決のトラブルはダッシュボードに表示 |
| セキュリティ管理 | 診断サービス契約（対象ドメインを登録）、外部診断の結果（レポートファイル添付可）、サーバー内部の不正ファイル検査、サイト別状況 |
| バックアップ管理 | WordPressバックアップ・サーバー全体バックアップを区別して記録。古い・未確認を表示 |
| 月次報告書 | 月を選んで報告書をプレビュー。「PDFで保存」「印刷用画面を開く」「CSV出力」 |
| 設定・データ管理 | 組織名・担当者・警告日数、チェック項目の編集、ユーザー管理、データのバックアップ・復元、一覧のCSV出力、Notion取り込み用CSV |

### 日常の流れ（例）

1. ダッシュボードで「点検が必要なサイト」「対応中の問題」を確認
2. 「＋ 点検する」でサイトを選び、確認した項目だけ結果を選んで保存
   （初期値は「未確認」。未確認のまま保存しても「問題なし」にはなりません）
3. 「要確認・対応中」にした項目はToDoに入るので、対応したら丸ボタンで完了にする
4. 診断レポートを受け取ったら「セキュリティ管理 → 外部診断の結果」で登録し、PDFを添付
5. 月末に「月次報告書」で特記事項を書いて保存し、「PDFで保存」して上司へ送付

### サイトの状態（色分け）の意味

| 色 | 意味 | 主な条件 |
|---|---|---|
| 赤 | 問題発生・至急対応 | 至急のトラブル・ToDoが未完了、重要度「高」以上の診断指摘が未対応、不審ファイル検出が未解決、SSL期限切れ、ドメイン期限超過 |
| 黄 | 確認が必要 | 点検で「要確認・対応中」、次回点検日超過、未完了のToDo、トラブル未解決、バックアップが古い、SSL・ドメインの期限が近い 等 |
| グレー | 未確認 | 点検記録なし・点検期限切れ、未確認の点検項目、SSL未確認、ドメイン期限が未登録、バックアップ記録なし、診断結果なし |
| 緑 | 確認済み・問題なし | 上記のどれにも当てはまらない場合のみ |

判定の理由は、ダッシュボードとサイト詳細に文章で表示されます。日数のしきい値は「設定」で変更できます。

### PDF・CSVについて

- **PDF**：「PDFで保存」を押すと印刷画面が開きます。送信先（プリンター）で **「PDFに保存」** を選ぶとA4のPDFになります。PCに入っている日本語フォントで作られるため文字化けしません。
- **CSV**：UTF-8（BOM付き）で出力するため、Excelでそのまま開いても文字化けしません。ファイル名は環境差による文字化けを避けるため半角英数字です（例：`site-report_2026-11.csv`）。

### Notionで管理したい場合

「設定・データ管理 → Notionに取り込む（CSV）」から、ToDoリスト・セキュリティチェック表（全サイトの最新結果）・サイト一覧（状態つき）をCSVで出力できます。Notionで「インポート → CSV」を選ぶとデータベース（表）として取り込めます。取り込み後に「状況」「優先度」列をセレクト型に変更すると、ボード表示やフィルターで使えます。

> この出力は一方向（このシステム → Notion）です。Notion側で変更した内容はこのシステムには戻りません。

## 4. データの保存場所

```
site-manager/
└─ data/                 ← 自動で作られます（Gitには含まれません）
   ├─ db.json            業務データ（サイト・点検・ToDo・作業・診断・バックアップ・設定）
   ├─ auth.json          ログイン用アカウント（パスワードはハッシュ化して保存）
   ├─ attachments/       添付ファイル（診断レポート等）
   └─ backups/           自動スナップショット（最新30件）
```

保存先を変えたい場合は、起動時に環境変数 `DATA_DIR` を指定します（例：`DATA_DIR=D:\site-data node server.js`）。

## 5. バックアップ方法

### 自動で行われるもの

- 1日1回、最初の保存時に `data/backups/` へ `db.json` の控えを作成
- サイトの削除・データの復元の直前にも控えを作成
- 最新30件を保持（古いものから自動削除）

### 手動で行うもの（推奨：月1回以上）

1. 「設定・データ管理」→「データのバックアップ・復元」
2. **「添付ファイルも含めて書き出す」** を押すと、1つのJSONファイルがダウンロードされます
3. ファイルを社内の安全な場所（NAS・共有ドライブ等）に保管します

または、システムを終了した状態で `data` フォルダごとコピーしても構いません（これが最も確実です）。

### 復元方法

1. 「設定・データ管理」→「バックアップから復元」でファイルを選択
2. 確認画面で「復元する」を押す（現在のデータは置き換えられ、復元前の状態は自動保存されます）

`data/backups/` 内の自動スナップショット（`db-日時.json`）も同じ方法で復元できます（添付ファイルは含まれません）。

> ログイン情報（`auth.json`）はバックアップファイルに含まれません。別のPCに移す場合は `data` フォルダごとコピーしてください。

## 6. 社内の他のPCからも使いたい場合

初期設定では、このPCからしか開けません（`127.0.0.1` で待ち受け）。社内LANの他のPCからも使う場合だけ、次のように起動します。

```bash
HOST=0.0.0.0 node server.js      # Windows(PowerShell): $env:HOST="0.0.0.0"; node server.js
```

**注意**：ルーター等でインターネット側に公開しないでください。通信は暗号化されていない（http）ため、社内ネットワーク内に限って利用してください。

## 7. このシステムで保存しないもの

- WordPress・サーバー・FTP・ドメイン管理画面などの **ID・パスワード・APIキー**
- 契約費用・支払い状況（別システムで管理）
- 必要以上の個人情報（担当者は名前のみ）

入力欄に「パスワード: 〜」のような記述があると、保存前に警告が表示されます。

## 8. サイトや点検項目が増えたとき

- サイトは「サイト管理台帳 →＋ サイトを追加」でいくつでも追加できます（10・20サイト以上でも同じ画面で管理できます）。
- 閉鎖したサイトは削除せず、「運用状況」を「運用終了」にすると履歴を残したまま集計から外れます。
- チェック項目は「設定 → 点検項目テンプレート」で種類ごとに追加・分類変更・並べ替え・削除できます。過去の点検記録は変わりません。

## 9. 困ったとき

| 症状 | 対処 |
|---|---|
| 画面が開かない | 黒い画面（サーバー）が起動しているか確認。`EADDRINUSE` と出る場合は別のポートで起動：`PORT=3801 node server.js` |
| ログインできない | 10回失敗すると15分間ロックされます。時間をおいて再試行してください |
| パスワードを忘れた | 他の管理者に新しいユーザーを作ってもらうか、システムを止めて `data/auth.json` を削除し再起動すると初回設定からやり直せます（業務データは消えません） |
| データを間違えて消した | 「設定 → バックアップから復元」で `data/backups/` の控えを選んで復元 |

## 10. フォルダ構成

```
site-manager/
├─ server.js                 サーバー本体（起動ファイル）
├─ server/
│  ├─ schema.js              入力検証（項目定義）
│  ├─ store.js               データ保存・スナップショット
│  ├─ auth.js                ログイン・セッション
│  └─ seed.js                初期データ（9サイト・点検項目）
├─ public/
│  ├─ index.html             管理画面
│  ├─ login.html             ログイン画面
│  ├─ report.html            報告書（印刷・PDF用）
│  └─ assets/
│     ├─ css/style.css       スタイル（1ファイル）
│     ├─ img/                ロゴ・ファビコン
│     └─ js/
│        ├─ app.js           ルーティング・レイアウト
│        ├─ labels.js        選択肢と日本語ラベル（サーバーと共通）
│        ├─ status.js        状態判定ロジック
│        ├─ editors.js       入力フォーム定義
│        ├─ report-*.js      報告書の集計・表示
│        └─ views/           各画面
├─ docs/DESIGN.md            設計書
├─ start.bat / start.command 起動用ファイル
└─ data/                     保存データ（自動作成）
```
